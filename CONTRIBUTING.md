# Contributing to Marivo

Thank you for contributing! This document describes the conventions for issues, pull requests, branches, and commits.

---

## Issue Conventions

### Title Format

Use **semantic commit** format, in **full lowercase**:

```
<type>(<scope>): <description>
```

- **type** (required): one of `feat`, `fix`, `refactor`, `build`, `chore`, `docs`, `test`, `perf`, `ci`, `security`
- **scope** (optional): `<component>` or `<component>/<subdomain>`
  - **component**: `api`, `webapp`, `worker`, `storefront`, `infra`
  - **subdomain** (when relevant):
    - **api**: `auth`, `script`, `plays`, `shared`, `infra`
    - **webapp**: `auth`, `script`, `components`, `layouts`, `lib`, `play-admin`
    - **worker**: `parser`, `jobs`, `s3`, `trpc`
- **description**: short, imperative, lowercase

### Examples

```
feat(api/script): add save line endpoint
fix(webapp/auth): resolve auth race condition on refresh
chore: upgrade dependencies to latest
security(worker/s3): remove hardcoded s3 credentials
ci: add github actions workflow
```

### Labels

Every issue must have **one** of these labels:

| Label | When to use |
|-------|-------------|
| `feature` | New functionality |
| `bug` | Something is broken |
| `refactor` | Code restructuring without behavior change |
| `build` | Build system, dependencies, CI/CD |
| `chore` | Maintenance, tooling |
| `security` | Security-related changes |
| `docs` | Documentation changes |

## Pull Request Conventions

### Title Format

```
<issue title> (#<issue-id>)
```

In **full lowercase**. The PR title must match the linked issue title, with the issue number appended in parentheses.

### Examples

```
feat(api/script): add save line endpoint (#42)
fix(webapp/auth): resolve auth race condition on refresh (#17)
chore: upgrade dependencies to latest (#100)
```

### Body

- Use `Closes #<issue-id>` to auto-link and close the issue on merge
- Describe what changed and why
- Include a testing section with manual test steps
- List any breaking changes

### Labels

Same label set as issues. The PR must carry the same label as its linked issue.

---

## Branch Naming

```
<type>/issue-<NNN>-<short-description>
```

### Examples

```
fix/issue-79-local-persistence
feat/issue-80-server-write-endpoints
chore/issue-99-contributing
```

## Commit Format

```
<type>(<scope>): <description>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

Same semconv format as issue titles, full lowercase. Scope uses `<component>` or `<component>/<subdomain>` (see Issue Conventions above).

## Code Quality Gates

Before pushing, run:

```bash
pnpm check-types   # TypeScript must pass
pnpm lint          # ESLint must pass (zero warnings)
pnpm test          # All tests must pass
pnpm build         # Build must succeed
```

See [AGENTS.md](./AGENTS.md) for testing requirements and architecture patterns.

---

## Creating Issues and PRs

Use the GitHub CLI:

```bash
# Create an issue
gh issue create --title "feat(api/script): add save line endpoint" --label "feature" --body "..."

# Create a PR
gh pr create --title "feat(api/script): add save line endpoint (#42)" --label "feature" --body "Closes #42"
```
