# AGENTS.md — Instructions for AI Agents Working on Marivo

> Read this file **before implementing any feature or fix**. It defines mandatory practices for code, tests, and PRs in this repository.

---

## 1. Testing is Mandatory

**Every PR must include tests.** No exceptions.

| Layer | What to test | Test type | Where |
|-------|-------------|-----------|-------|
| **API use cases** | Happy path + error cases | Unit tests (mock repositories) | `apps/api/src/**/*.test.ts` |
| **API endpoints** | Full request→response flow | Integration tests | `apps/api/src/**/*.integration.test.ts` |
| **Webapp utilities** | Pure functions, storage, reducers | Unit tests | `apps/webapp/src/**/*.test.ts` |
| **Webapp components** | Render, interaction, props | Unit tests (jsdom) | `apps/webapp/src/**/*.test.tsx` |
| **Worker (Python)** | Job processing, parsers | Unit tests (pytest) | `apps/worker/tests/` |

### Running Tests

```bash
# API (Node, ESM)
cd apps/api && pnpm test              # all tests
cd apps/api && pnpm test:unit         # unit only
cd apps/api && pnpm test:integration  # integration only

# Webapp (browser/jsdom)
cd apps/webapp && pnpm test

# All packages via turbo
pnpm test
```

### Test Requirements

- **Unit tests**: Mock all external dependencies (DB, S3, APIs). Test business logic in isolation.
- **Integration tests**: Test happy paths through the full stack (tRPC router → use case → repository with mocked DB).
- **Minimum coverage**: Every new use case must have at least 1 happy path + 1 error case test.
- **Naming**: `*.test.ts` for unit, `*.integration.test.ts` for integration.
- **Result type**: Use `result.isOk()`, `result.isFailure()`, `result.dataOrThrow()`, `result.errorOrThrow()` — NOT `isErr()`/`unwrap()`.

Before pushing, run:

```bash
pnpm check-types   # TypeScript must pass
pnpm lint          # ESLint must pass (zero warnings)
pnpm test          # All tests must pass
```

## 3. Branch & PR Conventions

- Branch: `fix/issue-NNN-description` or `feat/issue-NNN-description` or `chore/issue-NNN-description`
- PR title: `type(scope): description` (e.g., `fix(webapp): add localStorage persistence`)
- PR body must include `Closes #NNN`
- Use `gh` CLI for issues and PRs: `gh issue create`, `gh pr create`

### After Rebasing

**Always regenerate the lockfile after a rebase** to avoid CI failures from
lockfile/overrides mismatches:

```bash
git rebase origin/master
pnpm install --no-frozen-lockfile   # regenerate lockfile
pnpm install --frozen-lockfile      # verify it's in sync
git add pnpm-lock.yaml && git commit --amend --no-edit  # or new commit
git push --force-with-lease
```

If `pnpm install --frozen-lockfile` fails locally, the lockfile is stale —
regenerate it before pushing.

## 4. Architecture Patterns

- **API**: Domain-driven. Each domain has: `*.models.ts`, `*.repository.ts`, `*.use-case.ts`, `*.trpc-routes.ts`, `*.providers.ts`
- **Use cases**: Return `Result<TSuccess, TFailure>` from `@marivo/utils`. Never throw for expected errors.
- **Webapp**: Feature-based. Each feature in `src/features/<name>/` with co-located context, state, components.
- **State**: Reducer pattern for complex state (`script-state.ts`). Persist to localStorage for offline support.

## 6. File Naming

- Components: `*.component.tsx`
- Contexts: `*.context.tsx`
- State/reducers: `*.state.ts`
- Utilities: `*.utils.ts` or `*.lib.ts`
- Tests: `*.test.ts` / `*.integration.test.ts`
- CSS: `*.module.css`

---

## 7. Do NOT

- Commit `.env` files, secrets, or API keys
- Commit `.github/ISSUES/` or `.github/PRS/` (gitignored — use `gh` CLI)
- Commit `dist/` folders
- Skip tests "to save time"
- Use `any` types without justification
